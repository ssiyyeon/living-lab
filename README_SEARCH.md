# 검색 로직 설계 결과 (README_SEARCH)

> `data/manual/*.json`, `data/complaints/recurring_cases.json`을 소비해서 시민 민원 문장에
> 관련 매뉴얼/참고사례를 찾아주는 검색 엔진(`search/`)의 설계 과정과 판단 근거를 기록합니다.
> 방향은 사용자 피드백("실무에서 보통 쓰는 방식으로")에 따라 정했고, 구현 전 예시로 먼저
> 3가지 후보(키워드/TF-IDF/임베딩)를 실제 데이터로 데모한 뒤 하이브리드로 확정했습니다.

## 1. 현재 방식: BM25 어휘 검색

- **BM25**: Elasticsearch/Lucene/Solr가 기본으로 쓰는 어휘 검색 알고리즘(`rank_bm25`). 실무
  표준.
- **임베딩**: 문장을 벡터로 바꿔 의미 유사도로 비교(`sentence-transformers`,
  `paraphrase-multilingual-MiniLM-L12-v2`, 로컬 무료 모델 — API 비용·네트워크 의존 없음).
- 두 방식을 실제 질문으로 비교했지만, 아래 3번의 오탐 문제 때문에 현재 v1은 BM25만
  실행합니다. 임베딩 모델과 벡터도 인덱스에 포함하지 않아 초기 설치와 실행을 가볍게
  유지했습니다.

## 2. 구현 중 실측으로 발견하고 고친 문제 3가지

### (1) 한국어 조사 때문에 BM25가 정확한 단어도 못 찾음
`rank_bm25`에 그냥 띄어쓰기 기준 단어 토큰을 넣으면 "지하차도**에**"와 "지하차도"가 완전히
다른 토큰이 되어(조사가 붙어있어서) 형태소 분석기 없이는 정확히 겹치는 단어가 하나도 없는
것으로 계산됐습니다. → **문자 바이그램(CJK bigram) 토큰화**로 교체(Lucene의
`CJKBigramFilter`와 같은 원리, 형태소 분석기 없이 한국어 어휘검색을 돌릴 때 실무에서 흔히
쓰는 방법). "지하차도"를 "지하","하차","차도" 부분열로 쪼개면 조사가 붙어도 겹치는 부분이
남아서 정상적으로 매칭됩니다.

### (2) 표지·자체 목차표·타임라인 요약 같은 "메타 페이지"가 모든 질문에 걸림
바이그램 적용 직후 재검증하다가, 26p 하위 표지·52p 자체 목차표·2p 당직근무 타임라인
요약처럼 다양한 부서/상황 단어를 조금씩 다 언급하는 페이지가 **어떤 질문을 넣어도 상위권에
뜨는** 현상을 발견했습니다. 이런 페이지는 시민에게 줄 "답"이 아니라 내부 색인/개요용이라
검색 대상에서 제외했습니다(`search/build_index.py`의 `INDEX_PAGE_TITLE_MARKERS`).

### (3) 케이스 본문 전체를 색인하면 정형 문구 때문에 무관한 질문도 걸림
모든 재난/민원 케이스가 "본관 당직사령에게 상황보고", "관련 부서에 접수 사항 전파"처럼
거의 동일한 절차 문구를 공유하고 있어서, 본문 전체를 BM25에 넣으면 "무단횡단하는 사람이
많아요"처럼 완전히 무관한 문장도 아무 케이스에나 어중간하게 매칭되는 걸 실측으로 확인했습니다
(예: 이 질문이 "가로수 전도" 케이스와 9.16점으로 오매칭). → **BM25 색인은 제목+키워드만
사용**(본문 전체 제외)으로 바꿔서 해결. 본문은 결과 화면에 보여줄 표시용으로만 남겨뒀습니다
(`display_text` 필드).

## 3. 임베딩(의미 검색) 티어를 v1에서 끈 이유 — 정직하게 기록

수정 후에도 `search/calibrate.py`로 12개 질문(정답 7 + 오답 5)을 돌려보니, **무관한 질문의
임베딩 유사도가 진짜 정답보다 더 높게 나오는 역전 현상**이 나타났습니다.

| 질문 | 성격 | 임베딩 유사도(최고) |
|---|---|---|
| "밤에 노래방에서 시끄러운 소리가 계속 나요" → 소음 민원 | **진짜 정답** | 0.455 |
| "오늘 날씨가 좋네요" | 완전 무관 | 0.624 |
| "공무원이 불친절해요" | 완전 무관 | 0.654 |
| "무단횡단하는 사람이 너무 많아요" | 완전 무관 | 0.741 |

진짜 정답(0.455)보다 무관한 질문들(0.62~0.74)의 점수가 더 높아서, 전역 임계치 하나로는
참/거짓을 가를 수 없는 상태였습니다. 켜두면 "구어체 표현을 잡아낸다"는 이득보다 "엉뚱한
오탐이 더 많아진다"는 손해가 커서, **근거가 불확실한 채로 배포하지 않는다는 원칙에 따라
v1에서는 비활성화**했고 인덱스 빌드에서도 제외했습니다.

재활성화하려면 다음 중 하나가 필요합니다:
- 문서 텍스트를 더 길고 구체적으로(현재 반복민원 문서는 "유형명+부서명" 정도로 너무 짧음)
- 한국어 특화 임베딩 모델로 교체 후 `calibrate.py`로 재검증

## 4. 실행 방법

```bash
python -m venv .venv
# Windows: .venv\Scripts\python -m pip install -r backend\requirements.txt
# macOS/Linux: .venv/bin/python -m pip install -r backend/requirements.txt
python search/build_index.py   # data/manual, data/complaints를 읽어 search/index/ 빌드(최초 1회 + 데이터 갱신 시)
python search/calibrate.py     # 회귀 테스트(12개 질문)
python search/engine.py        # 데모 질의 5개 실행
```
`search/index/`는 재현 가능한 빌드 캐시라 git에는 올리지 않습니다(`.gitignore`).

## 5. 최종 검색 흐름 (`search/engine.py`)

```
질의 → 1) 매뉴얼 BM25 정확매칭 (임계치 6.0 이상) → tier: manual_exact
       → 2) [v1 비활성화] 매뉴얼 임베딩 의미매칭
       → 3) 반복민원 BM25 매칭 (임계치 5.0 이상) → tier: historical_case (공식 아님, 항상 명시)
       → 4) 전부 실패 → tier: no_match → "담당부서에 직접 문의해주세요"
```

## 6. 회귀 테스트 결과 (`search/calibrate.py`, 12개 질문)

**12/12 통과.** 표본이 작아 향후 실제 검색 로그가 쌓이면 테스트셋을 키우고 임계치도
다시 보정해야 합니다.

## 7. 알려진 한계

1. **구어체 재현율**: "시끄러운 소리"(→소음), "무단횡단" 같이 매뉴얼 키워드와 단어 자체가
   안 겹치는 질문은 `no_match`로 빠집니다(틀린 답을 주는 대신 안전하게 "담당부서 문의"로
   안내하는 쪽을 선택 — 위 3번 항목 참고).
2. **순위 품질**: "불법으로 주차한 차 단속해주세요" 질문에서 정답("불법주정차 신고")이
   1순위가 아니라 2순위로 나옵니다("불법투기, 불법소각 단속요청"이 비슷한 단어로 1순위를
   차지함). top-3를 다 보여줘서 실사용에 큰 문제는 없지만 순위 로직은 개선 여지가 있습니다.
3. **임베딩 티어 비활성화**: 위 3번 항목 참고, 재활성화는 추가 구현과 검증이 필요합니다.
